# עוזר הקטלוג

מחליף את מנוע הרגקסים ב-`askAssistant` (בערך 300 שורות של
`/תחליף|חלופי|החלפה|.../.test(question)`) בקריאה ל-Claude עם כלים.

## למה tool use ולא RAG

החיפוש בקטלוג כבר טוב. מה שחסר זו הבנת שפה. לכן המודל לא מקבל מסמכים
לקרוא — הוא מקבל את פונקציות החיפוש עצמן ככלים, ומחליט מה לקרוא ואיך
לנסח. הנתונים המדורגים נשארים מקור האמת, ולכן המודל **לא יכול להמציא
מק״ט**: כל מספר בתשובה הגיע מ-D1.

## הכלים

| כלי | מה עושה |
|---|---|
| `search_parts` | חיפוש מדורג לפי מק״ט או תיאור. כל צורות הכתיב של מק״ט מובילות לאותו חלק. אפשר לצמצם לקטלוג אחד. |
| `get_part` | רשומה מלאה של חלק: כל ההופעות, המכלולים, המיקומים בשרטוט והכמויות. |
| `list_assembly` | כל החלקים באותו שרטוט לפי סדר המיקומים — "מה עוד יש על הציור הזה". |
| `parts_for_vin` | ממפה מספר שלדה לקטלוג שלו, ומחפש בתוכו בלבד. |

כל הארבעה יושבים על `db/catalog-queries.ts` — אותו קוד שמשרת את נתיבי
ה-REST, כדי שהדירוג לא יתפצל לשתי מימושים.

## הפעלה

המפתח הוא סוד של ה-worker ואינו מגיע לדפדפן. בפיתוח: `.dev.vars` עם
`ANTHROPIC_API_KEY=...`. בייצור: להגדיר את הסוד בפלטפורמה.

בלי מפתח הנתיב מחזיר 503 עם הסבר, ולא נופל.

## הפרוטוקול

`POST /api/assistant` עם `{ messages, language, vin?, catalog? }`, ומחזיר SSE:

| אירוע | מתי |
|---|---|
| `tool` | המודל קרא לכלי — לתצוגת "מחפש בקטלוג..." |
| `text` | קטע טקסט מהתשובה |
| `done` | סיום, עם `stopReason` |
| `error` | תקלה, כולל שגיאות API |

מודל `claude-opus-5` עם `thinking: {type:"adaptive"}` וסטרימינג.

## מה נבדק ומה לא

נבדק: 503 בלי מפתח, 400 על גוף לא תקין ועל בקשה בלי הודעות, ושה-SSE
נפתח וזורם — עם מפתח לא תקין ה-401 חוזר כאירוע `error` תקין ולא כקריסה.
ארבעת הכלים נבדקו דרך נתיבי ה-REST שחולקים איתם את אותו הקוד.

**לא נבדקה תשובה מוצלחת של Claude** — לסביבה שבה נכתב הקוד לא היה מפתח API.
זה הדבר הראשון שכדאי להריץ עם מפתח אמיתי.
